# Миграция talents v1 -> v2

Документ описывает QA-чеклист и контракт миграции старых сейвов в `TalentsV2`.

## Где вызывается

- Место: `src/systems/talents/talentsV2.js`, внутри `Game.TalentsV2.init(...) -> loadFromSave()`.
- Условие запуска:
  - если `save.talentsVersion` отсутствует или `< 2`, выполняется миграция;
  - если `talentsVersion >= 2`, миграция **не** запускается (идемпотентно).
- После успешной миграции в save сразу пишется:
  - `talentsVersion = 2`
  - `talentsV2 = { ranksById, freePoints }`
  - `freeTalentPointsV2 = freePoints`

## Контракт входа/выхода

### Вход (legacy v1)

Поддерживаются fail-soft источники:

- именованные коллекции (`talentsV1`, `legacyTalents`, `talentsByName`, `talents`),
- legacy массив `talentsApplied` (индексы старого дерева v1),
- очки из `talentPoints`/`freeTalentPointsV1` и опционально `spentTalentPoints`/`talentPointsSpent`.

Каждый v1 элемент нормализуется к:

- `{ name: string, rank: number, bought: boolean }`

Правила нормализации:

- если хранится числовой rank -> `rank = число`, `bought = rank > 0`;
- если хранится bool «куплено» -> `rank = 1`, `bought = true`;
- если имя есть, но rank невалиден -> `rank = 1` (fail-soft);
- имя никогда не угадывается: неизвестное имя -> `unknown`.

### Выход (v2 patch)

Миграция формирует patch:

- `talentsVersion: 2`
- `talentsV2: { ranksById: Record<string, number>, freePoints: number }`
- `freeTalentPointsV2: number`

`ranksById` всегда clamp'ится по `maxRank` из `assets/balance/talentTree_v2.json`.

## Алгоритм миграции

1. Берётся canonical дерево v2, строится `maxRankById`.
2. Для каждого legacy-таланта применяется правило из `MIGRATE_V1_TO_V2` (см. код).
3. Если имя отсутствует в map -> очки уходят в `refund`.
4. Если несколько v1 имён мапятся в один v2 id -> ранги суммируются по правилам операций, затем clamp.
5. Считается `spentV2 = sum(ranksById[*])`.
6. Считаются `pointsV1 = { spent, free }`.
7. Считается `freePoints = max(0, (spent + free) - spentV2) + refund`.
8. Patch сохраняется сразу, чтобы миграция не повторялась на следующей загрузке.

## Политика refund / unknown / clamp

- `unknown` v1 имя не ломает загрузку.
- Стоимость unknown (`rank`) всегда возвращается через `refund`.
- Любой результат маппинга ограничивается `maxRank` соответствующего v2 таланта.

## Каноническая map-таблица

- Источник правды: `MIGRATE_V1_TO_V2` в `src/systems/talents/talentsV2.js`.
- Для добавления нового legacy имени в будущем достаточно:
  1) добавить ключ в `MIGRATE_V1_TO_V2`,
  2) выбрать op (`addRankFromOld`, `addRankIfBought`, `setRankIfBought`, `ensureMinRank`),
  3) при необходимости задать `value`.

## Поддерживаемые старые имена (v1)

Поддерживаются все ключи `MIGRATE_V1_TO_V2`, включая:

- Атака/Наступление: `Калибр`, `Бронебойные`, `Кислотный урон`, `Горящий яд`, `Контроль зоны`, `Огневой поток`, `Снайперский финал`, `Активка: Шквал`, `Фокусировка`, `Дальний выстрел`, `Разрывные боеприпасы`, `Широкий взрыв`, `Отравляющие осколки`, `Токсичная волна`.
- Скорость/Наступление: `Синхронизация`, `Импульс`, `Сверхскорострельность`, `Калибровка затвора`, `Турбозатвор`, `Стартовый импульс`, `Активка: Перегрев`, `Механизм спарки`, `Двойной выстрел`, `Серия`, `Дуплет`, `Разгон орбиты`, `Стабильная орбита`, `Рывок орбиты`.
- Экономика: `Скидки`, `Экономия топлива`, `Скидка на снаряды`, `Оптовые закупки`, `Контракт века`, `Увеличенный выкуп`, `Снабжение`, `Казначей`, `Программа лояльности`, `Бонус за выстрел`, `Премия за убийство`, `Копилка опыта`, `Инвестор`, `Стимул обучения`, `Ускоренное обучение`, `Золотая лихорадка`.

## QA checklist

> **Важно**: код V1 талантов полностью удалён из кодовой базы (файл `talentDefs.js` удалён, все V1-функции убраны из `game.js`). Миграционный код в `talentsV2.js` (`MIGRATE_V1_TO_V2`, `loadFromSave`) по-прежнему работает и корректно переносит старые save. Поле `talentsApplied` сохраняется в state для обратной совместимости миграции.

1. Подготовить legacy save без `talentsVersion`.
2. Загрузить игру -> убедиться, что ошибок в консоли нет.
3. Проверить после загрузки:
   - `talentsVersion === 2`
   - есть `talentsV2.ranksById`
   - есть `talentsV2.freePoints` и `freeTalentPointsV2`
4. Для unknown legacy имени проверить:
   - миграция не падает,
   - `freePoints` увеличивается на его стоимость.
5. Для дублей (несколько v1 -> один v2) проверить суммирование + clamp.
6. Для `Премия за убийство` проверить `eco_coins_kill_bonus >= 3` (или clamp к maxRank).
7. Повторная загрузка save с `talentsVersion=2` не меняет данные.
