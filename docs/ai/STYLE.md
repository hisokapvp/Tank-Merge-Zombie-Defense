# STYLE — правила правок (проверяемые)

## Быстрый ответ

- Новую логику добавляй в `src/*`, не раздувай `game.js` без необходимости.
- В `draw()` не добавляй бизнес-логику и I/O.
- Любой новый UI-текст должен идти через i18n (`src/i18n/ru.json`, `src/i18n/en.json`).

## JavaScript (проектный стандарт)

1. **Модули в `src/*` публикуются через `global.Game.*`**.
   - Пример: `global.Game.Economy = { ... }`.
   - Контрпример: анонимные функции без публичного API при необходимости повторного использования.

2. **Правила/формулы выноси в system-модули, не в UI**.
   - Пример: `src/mechanics/economy.js`, `src/mechanics/combat.js`.
   - Контрпример: расчёт урона внутри DOM-обработчика.

3. **Не создавать тяжёлые аллокации в hot-path** (`loop`, `draw`, массовые `step*`).
   - Применяй pooling (`src/perf/objectPool.js`) где churn высокий.

4. **Локальное хранилище только через system APIs**.
   - Пример: `Game.Storage`, `Game.Telemetry`, `Game.Flags`, `Game.Experiments`.
   - Контрпример: разрозненные `localStorage.setItem` в случайных местах.

5. **Нейминг функций**: глагол + сущность (`computeOfflineRewards`, `updateBuyButtonState`).

## Canvas/render

1. **`draw()` только рисует, не меняет экономику/прогресс/сохранение**.
2. **`loop()` управляет порядком update → UI → draw**.
3. **FPS/quality лимиты меняй через `Game.MobileMode`**.
4. **DPR/resize логика — через `resizeCanvas` и `CanvasRoot`-паттерн**.

## HTML

1. Модалки должны иметь `role="dialog"` и `aria-modal="true"`.
2. Для интерактивных элементов использовать `button`, не `div` с click.
3. Текстовые узлы для локализации — `data-i18n` где возможно.

## CSS

1. Цвета/тени — через переменные в `:root` (не добавлять хаотичные hex везде).
2. Не переопределять глобально без необходимости.
3. UI-селекторы должны соответствовать существующей структуре (`stage*`, `menu*`, `levelModal*`, `mergePopup*`).

## A11y

1. Новая модалка регистрируется в `Game.A11y` (`registerModal/openModal/closeModal`).
2. Escape закрывает модалку, Tab не выходит за её пределы.

## Тесты и проверки

- Базово перед merge:
  - `bash ci/check_style.sh`
  - `bash ci/run_tests.sh`

## DoD для любой правки

Правка считается завершённой, если:

1. Изменён код + обновлён A2DP (как минимум `INDEX.md` и затронутый `SYSTEMS/*.md`).
2. Обновлены i18n-строки (если менялся пользовательский текст).
3. Пройдены релевантные тесты/чек-листы.
4. Нет битых ссылок и устаревших путей в `docs/ai/*`.

## PR checklist (короткий)

- [ ] Обновил `docs/ai/INDEX.md` при перемещении/добавлении модулей.
- [ ] Обновил нужный `docs/ai/SYSTEMS/*.md`.
- [ ] При новой типовой операции добавил/обновил playbook.
- [ ] Добавил запись в `docs/ai/CHANGELOG.md`.
